01Academic ML project

Explainable AI-Powered Fraud Detection

Pythonscikit-learnRandom ForestRisk analytics
Problem / context
Only 492 of 284,807 source transactions were labelled fraud, so accuracy could exceed 99% while detecting none.
Contribution & decision
I built the reproducible pipeline, compared three classifiers, and selected both the Random Forest model and its 0.6735 alert threshold using validation data only rather than tuning on the test set.
What was difficult
Extreme class imbalance made accuracy misleading. I used stratified splits and evaluated precision, recall, F1, Average Precision, ROC-AUC, alert volume, and false-positive metrics instead.
Outcome
On the untouched test set: 95.7% precision, 69.5% recall, 0.805 F1, and 0.965 ROC-AUC; 69 of 56,746 transactions were escalated, with 66 confirmed fraud cases and 3 false positives.

02Systems programming

Deep Packet Inspection System

PythonPCAPThreadingCLI
Problem / context
The engine explores authorised offline PCAP classification and filtering from protocol metadata without decrypting TLS or performing live interception.
Contribution & decision
I wrote binary parsers and metadata extractors, then designed single- and multi-threaded paths with a reader, load balancer, fast-path workers, and writer.
What was difficult
Parallel packet handling can break stateful flow tracking. I used five-tuple tracking and consistent hashing to preserve flow affinity across workers.
Outcome
The standard-library-only tool classifies 20+ applications and services and passed 90 automated tests at a 100% pass rate.

01Security systems project

Deep Packet Inspection System

PythonNetwork securityTLS SNIPCAP
Problem / context
The system classifies authorised offline PCAP traffic from TLS SNI, HTTP Host, DNS, port, and IP metadata without decrypting encrypted payloads.
Contribution & decision
I implemented parsers for Ethernet, IPv4, TCP, and UDP, metadata extraction, 20+ application rules, and filtering by IP, application, domain, or port.
What was difficult
Multi-threading must preserve stateful flows. I handled this with consistent five-tuple hashing so a flow retains affinity with one worker.
Outcome
The offline, standard-library-only engine supports 20+ classifications and passed 90 automated tests at a 100% pass rate.
